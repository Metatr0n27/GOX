# GOX FIRST-DOLLAR EASY JOBS LANE

## PRIME DIRECTIVE
Optimize for verified dollars collected per unit of owner effort. Agent count is not a success metric.

## ZERO-BLOCKER PILOT RULE
The first-dollar pilot must use work that GOX can actually execute with the tools available under owner supervision without waiting on another person, winning a bespoke client, or depending on a human-only assessment/work step before the paid task can begin.

A candidate is rejected from the pilot if any required pre-task or task step is a blocker, including:
- platform-required unaided human assessment
- task instructions that prohibit the assistance GOX would need
- waiting for a client/requester to hire or select us before work can start
- unavailable/empty task queue
- unavailable payout method for the assigned lane
- unresolved identity/eligibility mismatch
- another person's participation or approval being required
- fabricated credentials, account sharing, identity borrowing, or cross-family impersonation

Owner-bound onboarding such as truthful identity, login/MFA/CAPTCHA, tax/payment setup, or consent may be surfaced as a gate only when unavoidable. These gates do not make the platform an Easy Job unless, immediately after completion, there is a real paid task GOX can execute within the rules.

## ACCEPTABLE FIRST-DOLLAR WORK
- hourly task queues already open to eligible workers
- piece-rate or per-item paid work
- data labeling / AI evaluation where rules permit assistance
- transcript/document cleanup
- spreadsheet/CSV cleanup
- public-web research and contact/data normalization where platform rules permit
- bounded extraction/classification tasks
- other legitimate available work a person could reasonably sit down and perform without first winning a bespoke client contract

## NOT AN EASY JOB FOR FIRST-PILOT PURPOSES
- speculative proposals that require a client to choose us before work can begin
- jobs with unknown payment legitimacy
- queues with no current task visibility after onboarding
- roles requiring fabricated credentials or expertise
- any task whose rules prohibit the assistance GOX would provide
- any path requiring a platform-required unaided human qualification before paid work becomes available
- account sharing, identity borrowing, or cross-family impersonation

## SECONDARY LANE
Freelance/contract marketplaces remain useful, but proposals are secondary to available paying task queues for the first-dollar objective.

## QUALIFICATION GATE
Every candidate must pass:
- payment legitimacy
- worker eligibility
- platform terms/automation policy
- correct account identity
- task is actually available now
- no blocking human-only precondition before paid work can begin
- payout method can be used by the assigned lane
- GOX capability fit is verified, not invented
- expected owner effort is measured
- no prohibited credential sharing or impersonation

## SCORECARD
Score 0-5 each:
- available now
- payout certainty
- expected net dollars
- repeatability
- GOX assistance fit
- low owner minutes
- low rejection risk
- low policy risk

Payout latency is tracked but is not a rejection reason by itself. A 39-day payout can still beat a fast-paying task if it is easier, more certain, or more repeatable.

Reject any task with a blocker, unclear payment legitimacy, or prohibited automation regardless of score.

## CURRENT PILOT ORDER
1. **Blocker-free live task source** — first source with visible paid work that GOX can execute under owner supervision within the task rules.
2. **Clickworker regular jobs** — only if onboarding leads directly to suitable visible paid work and no human-only qualification blocks the task.
3. **UHRS through Clickworker** — only if the required qualification can be completed without violating platform rules and does not depend on an unaided-human requirement that GOX cannot satisfy.
4. **Next qualified microtask/task queue** — immediate fallback whenever a blocker appears.

## EXECUTION LOOP
AVAILABLE TASK -> zero-blocker check -> qualify -> reserve/accept if platform rules allow -> compile canonical Easy Prompt -> independent-agent ensemble when assistance is permitted -> synthesize -> execute -> QA -> owner gate only if unavoidable -> submit -> capture evidence -> record economics -> repeat.

## FIRST TARGET CLASSES
1. CSV/spreadsheet normalization and cleanup
2. document/transcript cleanup
3. public web research / structured extraction
4. AI-output evaluation / annotation when platform rules allow
5. tagging/classification queues

## EVIDENCE PACK
For every attempt record:
- source/platform
- task identifier
- assigned identity/lane
- terms/policy check result
- blocker check result
- start/end timestamps
- raw input hash or source reference
- agent prompt ID
- outputs and QA result where storage is permitted
- owner actions/minutes
- submission evidence
- payout status
- gross/fees/net
- failure/rejection reason if any

Do not copy confidential task content into public repositories or logs. Use hashes, IDs, timestamps, and economics when task data is restricted.

## FAMILY LANE RULE
Each family member remains a separate identity/account/session/eligibility lane. Shared prompts, tools, and lessons may be reused only where platform rules permit. Never merge identities or secretly share accounts.

## FIRST-DOLLAR SUCCESS CONDITION
At least one legitimate blocker-free task is completed and accepted/paid, with net revenue > $0 and the full evidence/economics record written to the ledger.
